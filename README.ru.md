# yunheshiguang

[English](./README.md) · [العربية](./README.ar.md) · [中文](./README.zh-CN.md) · [Français](./README.fr.md) · **Русский** · [Español](./README.es.md)

Настольное рабочее место для управления парками Android-устройств с одного компьютера: подключайте их, наблюдайте за ними и управляйте ими пакетно. Построено на Tauri 2 (бэкенд на Rust, интерфейс на React). Устройства подключаются через ADB, и на них ничего не нужно устанавливать.

## Возможности

- **Стена устройств**: USB, Wi-Fi (сопряжение и обнаружение через mDNS) и облачные телефоны подключаются в одном месте. Сервер ADB сам сообщает об изменениях устройств, без периодического опроса. Устройствам можно присваивать номера, имена, теги и группы. Серийные номера и другие конфиденциальные данные по умолчанию скрыты, и по скрытым значениям поиск не работает.
- **Пакетные операции**: снимок экрана, запись экрана, установка APK, загрузка файла, ввод текста, запись в буфер обмена, запуск и остановка приложения, удаление приложения, очистка данных, восстановление подключения и запуск скрипта. Необратимые действия, например удаление приложения или очистка данных, сначала требуют подтверждения.
- **Трансляция экрана**: открывает окно для каждого устройства с помощью официального [scrcpy](https://github.com/Genymobile/scrcpy), который скачивается прямо из приложения с закреплённой версией и хешем SHA-256.
- **Автоматизация**: редактор сценариев, стартовые шаблоны, запуск по расписанию cron и история запусков. Сценарии выполняются в бэкенде; интерфейс только запускает и останавливает их и показывает ход выполнения.
- **Скрипты**: консоль shell-скриптов, которая возвращает вывод и код завершения с каждого устройства.
- **Черновики от ИИ**: опишите сценарий или скрипт одной фразой, и ИИ подготовит черновик, который появляется по мере написания. Черновики только открываются в редакторе; сохранять и запускать их всегда решаете вы. Работает с любым API, совместимым с OpenAI (OpenAI, DeepSeek, Qwen, локальный Ollama и другие); ключи остаются в бэкенде на этом компьютере.
- **Управление и отчёты**: каждое действие записывается вместе с оператором. Журнал аудита хранится в локальной базе SQLite, его можно фильтровать и экспортировать в CSV или JSON Lines. Отчёты суммируют операции по группам, операторам, действиям и дням.
- **Пакеты шаблонов**: делитесь сценариями и скриптами в виде пакетов с хешем содержимого, при желании подписанных с помощью [minisign](https://jedisct1.github.io/minisign/). Перед установкой предпросмотр показывает, кем подписан пакет.
- **Локальный API**: HTTP и WebSocket для скриптов и других систем. По умолчанию выключен.
- **Интерфейс**: китайский и английский языки, светлая и тёмная темы.

## Поддерживаемые системы

| Система | Системный или указанный вручную ADB | Загрузка Platform Tools | Загрузка scrcpy |
| --- | --- | --- | --- |
| Windows x86-64 | Да | Да | Да |
| Windows ARM64 | Да | Нет | Да |
| macOS (Intel, Apple silicon) | Да | Да | Да |
| Linux x86-64 (glibc) | Да | Да | Да |
| Другие Linux | С совместимым ADB | Нет | Нет |

Приложение скачивает официальные Android Platform Tools 37.0.0 после того, как вы примете лицензию Android SDK. Адреса, размеры и хеши SHA-256 закреплены в исходном коде; несовпадающий пакет отклоняется ещё до распаковки.

## Начало работы

Нужны Node.js 24, pnpm 10, Rust 1.98.1 (выбирается через `rust-toolchain.toml`) и [системные зависимости Tauri](https://v2.tauri.app/start/prerequisites/).

```sh
pnpm install
pnpm tauri dev      # запустить настольное приложение
pnpm tauri build    # собрать установщики
```

Чтобы работать только над интерфейсом, запустите `pnpm dev` и откройте <http://localhost:1420> в браузере. Без хоста Tauri интерфейсу отвечают реализации тех же сервисов Connect в памяти; в продакшен-сборки они не попадают.

## Загрузки и обновления

Установщики лежат на [странице релизов](https://github.com/yunheshiguang/yunheshiguang-android/releases):

- **Стабильный**: последний релиз, публикуется вручную по тегу версии.
- **Nightly**: предварительный релиз `nightly`, пересобирается после каждого изменения в `main`, прошедшего CI.

У всех релизов одинаковые имена файлов (`yunheshiguang-windows-x86_64-setup.exe`, `yunheshiguang-macos-arm64.dmg`, `yunheshiguang-macos-x86_64.dmg`, `yunheshiguang-linux-x86_64.AppImage`, `yunheshiguang-linux-x86_64.deb`, `yunheshiguang-linux-x86_64.rpm`), к ним прилагаются `SHA256SUMS` и `release.json`. Приложение раз в день проверяет свой канал (**Настройки → Обновления**) и, когда выходит более новая сборка, даёт ссылку на подходящий файл; само оно ничего не скачивает и не устанавливает. Сборки пока не подписаны сертификатом разработчика. Каналы, манифест и порядок публикации описаны в [docs/releases.md](./docs/releases.md).

## Локальный API

Включается в **Settings → Local API**. Слушает только `127.0.0.1`, по умолчанию на порту 47831. Токены выдаются на той же странице; каждый токен показывается один раз, а приложение хранит только его хеш. API обслуживает те же сервисы Connect, что и окна приложения, и отвечает клиентам Connect, gRPC и gRPC-Web. Каждому запросу, кроме `/v1/health`, нужен токен:

```sh
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{}' \
  http://127.0.0.1:47831/yunheshiguang.workspace.v1.WorkspaceService/GetWorkspaceSnapshot
```

`/v1/openapi.json` описывает все процедуры, которые обслуживает API (OpenAPI 3.1, генерируется из сервисов в `proto/`); процедуры, которые только читают данные, отвечают и на `GET`. Процедура доступна через API, если её определение в `proto/` помечено опцией `local_api`. `/v1/events` — это WebSocket с событиями рабочего пространства; браузеры, которые не могут задать для него заголовки, могут передать `?access_token=`. Действия через API проходят ту же авторизацию и тот же аудит, что и действия в окнах приложения, а у каждого клиента свой лимит запросов.

## Расширения

Сборка по умолчанию — это ядро с открытым исходным кодом, и кода расширений в ней нет. Расширение состоит из двух частей: `native` — крейт плагина Tauri, который зависит только от `crates/sdk` и `crates/contract`, и `web` — фронтенд-пакет, который обращается к хосту только через `yunheshiguang/sdk`. Расширения могут предоставлять авторизацию, идентификацию, лицензирование, хранилище и дополнительные получатели аудита, хранилище документов, источники шаблонов, способы подключения, телеметрию, адаптеры производителей, каналы ввода, движки скриптов, аутентификацию API, провайдеров ИИ и провайдеров облачных телефонов; всё, чего не предоставляет ни одно расширение, берётся из реализации ядра по умолчанию.

`extensions/reference` — эталонное расширение, которое реализует большую часть этого (политику авторизации Cedar, командную идентификацию, лицензию, общий для команды аудит, хранилище в синхронизируемой папке, магазин шаблонов, облачные телефоны Redroid, провайдера ИИ для нативных API вроде Claude и Gemini, метрики Prometheus, адаптер для ферм плат, ввод через ADBKeyBoard, движок скриптов AutoJs6, корпоративные ключи API и корпоративную страницу):

```sh
pnpm tauri dev --config src-tauri/tauri.reference.conf.json   # запуск с эталонным расширением
pnpm dev --mode reference                                      # только интерфейс
```

## Разработка

| Команда | Что делает |
| --- | --- |
| `pnpm test` | Biome, ограничение длины файлов, слои FSD (Steiger), границы импортов, Knip, контракт между фронтендом и бэкендом и Vitest |
| `pnpm build` | Проверяет типы и собирает фронтенд |
| `pnpm check:distributions` | Собирает открытую версию и каждый составной дистрибутив и проверяет, что в открытой версии нет кода расширений |
| `pnpm proto:lint` / `pnpm proto:generate` / `pnpm proto:openapi` / `pnpm proto:verify` | Проверяет контракты, заново генерирует привязки TypeScript, заново генерирует документ OpenAPI и проверяет, что документ в репозитории актуален |
| `cargo test --workspace --all-features` | Тесты Rust, включая сборку с расширениями |
| `pnpm lint:rust` / `pnpm lint:deps` | clippy (`-D warnings`) и cargo-deny |

Контракты в `proto/` — единственный источник истины: `pnpm install` генерирует привязки TypeScript в `src/shared/proto/gen/` (в репозиторий не попадают), а привязки Rust генерируются при сборке.

## Сторонние компоненты

- [YADB](https://github.com/ysbing/YADB) v1.1.2 (LGPL-3.0): вводит текст и записывает буфер обмена устройства; встроен без изменений в `src-tauri/assets/yadb`.
- [Android SDK Platform Tools](https://developer.android.com/tools/releases/platform-tools): скачиваются по запросу после принятия их лицензии; с приложением не распространяются.
- [scrcpy](https://github.com/Genymobile/scrcpy) (Apache-2.0): официальные выпуски скачиваются по запросу; с приложением не распространяется.
