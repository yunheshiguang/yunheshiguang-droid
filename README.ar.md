# yunheshiguang

[English](./README.md) · **العربية** · [中文](./README.zh-CN.md) · [Français](./README.fr.md) · [Русский](./README.ru.md) · [Español](./README.es.md)

منصة عمل مكتبية لإدارة أساطيل من أجهزة Android من حاسوب واحد: توصيلها ومراقبتها وتشغيلها على دفعات. مبنية على Tauri 2 (واجهة خلفية بلغة Rust وواجهة أمامية بـ React). تتصل الأجهزة عبر ADB دون الحاجة إلى تثبيت أي شيء عليها.

## الميزات

- **جدار الأجهزة**: تتصل أجهزة USB وWi-Fi (الإقران والاكتشاف عبر mDNS) والهواتف السحابية من مكان واحد. يُبلغ خادم ADB بنفسه عن أي تغيّر في الأجهزة، دون استطلاع دوري. يمكن ترقيم الأجهزة وتسميتها ووسمها وتجميعها. تُخفى الأرقام التسلسلية وغيرها من البيانات الحساسة افتراضيًا، ولا يمكن البحث في القيم المخفية.
- **العمليات الدفعية**: لقطة الشاشة، وتسجيل الشاشة، وتثبيت APK، ورفع ملف، وإدخال نص، والكتابة في الحافظة، وتشغيل تطبيق أو إيقافه، وإلغاء التثبيت، ومسح البيانات، واستعادة الاتصال، وتشغيل برنامج نصي. تطلب الإجراءات التي لا يمكن التراجع عنها، مثل إلغاء التثبيت أو مسح البيانات، تأكيدًا مسبقًا.
- **عرض الشاشة**: يفتح نافذة لكل جهاز باستخدام [scrcpy](https://github.com/Genymobile/scrcpy) الرسمي، الذي يُنزَّل من داخل التطبيق بإصدار وبصمة SHA-256 ثابتين.
- **الأتمتة**: محرر للتدفقات، وقوالب للبدء، وجداول تشغيل بصيغة cron، وسجل للتشغيل. تُنفَّذ التدفقات في الواجهة الخلفية، ويقتصر دور الواجهة على تشغيلها وإيقافها وعرض تقدّمها.
- **البرامج النصية**: وحدة تحكم لبرامج shell النصية تُرجع مخرجات كل جهاز ورمز الخروج.
- **مسودات بالذكاء الاصطناعي**: صِف تدفقًا أو برنامجًا نصيًا في جملة واحدة، فيكتب الذكاء الاصطناعي مسودة تظهر أثناء كتابتها. تُفتح المسودات في المحرر فقط، ويبقى الحفظ والتشغيل قرارك دائمًا. يعمل مع أي واجهة برمجة متوافقة مع OpenAI (OpenAI وDeepSeek وQwen وOllama المحلي وغيرها)، وتبقى المفاتيح في الواجهة الخلفية على هذا الحاسوب.
- **الحوكمة والتقارير**: يُسجَّل المشغّل مع كل إجراء. يُحفَظ سجل التدقيق في قاعدة بيانات SQLite محلية، ويمكن تصفيته وتصديره بصيغة CSV أو JSON Lines. تُجمِّع التقارير العمليات حسب المجموعة والمشغّل والإجراء واليوم.
- **حزم القوالب**: شارك التدفقات والبرامج النصية في حزم تحمل بصمة لمحتواها، ويمكن توقيعها اختياريًا بـ [minisign](https://jedisct1.github.io/minisign/). تعرض المعاينة قبل التثبيت الجهة الموقِّعة.
- **واجهة برمجة محلية**: عبر HTTP وWebSocket للبرامج النصية والأنظمة الأخرى، وهي معطّلة افتراضيًا.
- **الواجهة**: باللغتين الصينية والإنجليزية، مع سمتين فاتحة وداكنة.

## الأنظمة المدعومة

| النظام | ADB المثبَّت أو المحدَّد يدويًا | تنزيل Platform Tools | تنزيل scrcpy |
| --- | --- | --- | --- |
| Windows x86-64 | نعم | نعم | نعم |
| Windows ARM64 | نعم | لا | نعم |
| macOS (Intel وApple silicon) | نعم | نعم | نعم |
| Linux x86-64 (glibc) | نعم | نعم | نعم |
| توزيعات Linux الأخرى | مع ADB متوافق | لا | لا |

ينزّل التطبيق حزمة Android Platform Tools الرسمية 37.0.0 بعد موافقتك على ترخيص Android SDK. العناوين والأحجام وبصمات SHA-256 ثابتة في الشيفرة المصدرية، وتُرفَض أي حزمة غير مطابقة قبل فك ضغطها.

## البدء

المتطلبات: Node.js 24 وpnpm 10 وRust 1.98.1 (يختاره `rust-toolchain.toml`)، إضافة إلى [متطلبات النظام الخاصة بـ Tauri](https://v2.tauri.app/start/prerequisites/).

</div>

```sh
pnpm install
pnpm tauri dev      # تشغيل تطبيق سطح المكتب
pnpm tauri build    # بناء حزم التثبيت
```

<div dir="rtl">

للعمل على الواجهة وحدها، شغّل `pnpm dev` وافتح <http://localhost:1420> في المتصفح. في غياب مضيف Tauri، تجيب الواجهةَ تطبيقاتٌ في الذاكرة لخدمات Connect نفسها، ولا تُضمَّن في بنيات الإنتاج.

## التنزيلات والتحديثات

حزم التثبيت موجودة في [صفحة الإصدارات](https://github.com/yunheshiguang/yunheshiguang-android/releases):

- **المستقر**: أحدث إصدار، يُنشر يدويًا انطلاقًا من وسم إصدار.
- **الليلي**: الإصدار التجريبي `nightly`، ويُعاد بناؤه بعد كل تغيير على `main` يجتاز CI.

لكل الإصدارات أسماء الملفات نفسها (`yunheshiguang-windows-x86_64-setup.exe`, `yunheshiguang-macos-arm64.dmg`, `yunheshiguang-macos-x86_64.dmg`, `yunheshiguang-linux-x86_64.AppImage`, `yunheshiguang-linux-x86_64.deb`, `yunheshiguang-linux-x86_64.rpm`)، ومعها `SHA256SUMS` و`release.json`. يتحقق التطبيق من قناته مرة في اليوم (**الإعدادات ← التحديثات**)، وعند صدور بنية أحدث يعرض رابطًا إلى الملف المناسب له؛ ولا ينزّل أو يثبّت أي شيء من تلقاء نفسه. البنيات غير موقّعة بشهادة مطوّر حتى الآن. يشرح [docs/releases.md](./docs/releases.md) القنوات وملف البيان وطريقة نشر إصدار.

## واجهة البرمجة المحلية

فعّلها من **Settings → Local API**. لا تستمع إلا على `127.0.0.1`، وعلى المنفذ 47831 افتراضيًا. تُصدَر الرموز المميزة من الصفحة نفسها، ويُعرَض كل رمز مرة واحدة فقط، ولا يحفظ التطبيق سوى بصمته. تقدّم واجهة البرمجة خدمات Connect نفسها التي تستخدمها نوافذ التطبيق، لعملاء Connect وgRPC وgRPC-Web على حد سواء. يحتاج كل طلب، عدا `/v1/health`، إلى رمز مميز:

</div>

```sh
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{}' \
  http://127.0.0.1:47831/yunheshiguang.workspace.v1.WorkspaceService/GetWorkspaceSnapshot
```

<div dir="rtl">

يصف `/v1/openapi.json` جميع الإجراءات التي تقدّمها واجهة البرمجة (OpenAPI 3.1، مولَّد من الخدمات في `proto/`)، وتستجيب الإجراءات التي تقرأ البيانات فقط لطلبات `GET` أيضًا. ولا تُقدَّم عبر واجهة البرمجة إلا الإجراءات التي يحمل تعريفها في `proto/` الخيار `local_api`. أما `/v1/events` فهو WebSocket يبث أحداث مساحة العمل، ويمكن للمتصفحات، التي لا تستطيع تعيين الترويسات له، تمرير `?access_token=` بدلًا من ذلك. تخضع الإجراءات المنفَّذة عبر واجهة البرمجة للتفويض والتدقيق نفسيهما المطبَّقين على نوافذ التطبيق، ولكل جهة مستدعية حدّ طلبات مستقل.

## الإضافات

البناء الافتراضي هو النواة مفتوحة المصدر، ولا يحتوي على أي شيفرة للإضافات. تتكون الإضافة من جزأين: `native`، وهي حزمة crate لملحق Tauri لا تعتمد إلا على `crates/sdk` و`crates/contract`، و`web`، وهي حزمة واجهة أمامية لا تصل إلى المضيف إلا عبر `yunheshiguang/sdk`. يمكن للإضافات توفير التفويض، والهوية، والترخيص، وتخزين التدقيق ووجهاته الإضافية، وتخزين المستندات، ومصادر القوالب، وطرق الاتصال، والقياس عن بُعد، ومحوّلات الشركات المصنِّعة، وقنوات الإدخال، ومحركات البرامج النصية، والمصادقة على واجهة البرمجة، ومزوّدي الذكاء الاصطناعي، ومزوّدي الهواتف السحابية؛ وكل ما لا توفّره أي إضافة يُستخدم فيه التنفيذ الافتراضي للنواة.

`extensions/reference` هي الإضافة المرجعية، وتنفّذ معظم ذلك (سياسة تفويض Cedar، وهوية الفريق، وترخيصًا، وتدقيقًا مشتركًا بين أعضاء الفريق، وتخزينًا في مجلد متزامن، وسوقًا للقوالب، وهواتف Redroid السحابية، ومزوّد ذكاء اصطناعي لواجهات البرمجة الأصلية مثل Claude وGemini، ومقاييس Prometheus، ومحوّلًا لمزارع اللوحات، والإدخال عبر ADBKeyBoard، ومحرك البرامج النصية AutoJs6، ومفاتيح واجهة برمجة للمؤسسات، وصفحة للمؤسسة):

</div>

```sh
pnpm tauri dev --config src-tauri/tauri.reference.conf.json   # التشغيل مع الإضافة المرجعية
pnpm dev --mode reference                                      # الواجهة فقط
```

## التطوير

| الأمر | ما يفعله |
| --- | --- |
| `pnpm test` | Biome، وحد طول الملفات، وطبقات FSD (Steiger)، وحدود الاستيراد، وKnip، والعقد بين الواجهتين الأمامية والخلفية، وVitest |
| `pnpm build` | يتحقق من الأنواع ويبني الواجهة الأمامية |
| `pnpm check:distributions` | يبني النسخة مفتوحة المصدر وكل توزيعة مركّبة، ويتأكد من خلو النسخة مفتوحة المصدر من شيفرة الإضافات |
| `pnpm proto:lint` / `pnpm proto:generate` / `pnpm proto:openapi` / `pnpm proto:verify` | يفحص العقود، ويعيد توليد روابط TypeScript، ويعيد توليد مستند OpenAPI، ويتحقق من أن المستند المحفوظ في المستودع محدَّث |
| `cargo test --workspace --all-features` | اختبارات Rust، بما فيها البناء المركّب مع الإضافات |
| `pnpm lint:rust` / `pnpm lint:deps` | clippy (`-D warnings`) وcargo-deny |

العقود في `proto/` هي المصدر الوحيد للحقيقة: يولّد `pnpm install` روابط TypeScript في `src/shared/proto/gen/` (لا تُحفظ في المستودع)، وتُولَّد روابط Rust أثناء البناء.
